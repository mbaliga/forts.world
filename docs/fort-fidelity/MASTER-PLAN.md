## Why not "5 forts per chat"
Hand-reconstructing 4,500 sites at 5 per chat is ~900 chats. Not realistic. So use a pyramid: automate the base, hand-craft the top.

| Pop. | Tier target | Method | Planning count* |
|---|---|---|---|
| All geolocated sites | T1 Located (auto) | Pipeline: OSM outline + Terrarium DEM + water, rendered by one parametric "real-outline" builder | ~3,000-4,000 |
| Significant sites with plans/photos | T2 Fitted (assisted) | Human-in-loop tracing from plans, 10-15 per chat once template exists | ~300 |
| Flagship forts | T3/T4 Phased + reviewed | Hand-authored, ~3-5 per chat | ~60-100 |
*Planning numbers; Phase 0 counts above give the real size of the T1 base.

## Phases
0a. **Build the full site universe** (Action-fetched, ODbL/CC0 sources): Wikidata (heritage-designated sites in South Asia by type), OSM `historic=*`/`building=temple` etc., ASI centrally protected monuments (~3,600 listed), state-protected lists, UNESCO tentative+inscribed, Smith-Newton, plus existing catalogue. Expect well over 10,000 raw entries; rank by significance (designation, Wikipedia language count, visitor/scholarly attention) to choose the working set.
0b. **Typology.** Each site gets a type (fort, palace, ancient-city, monastery/university, temple, stepwell, tomb, port...) because the builder, scene mechanics and sources differ. Temples/monasteries need plan-and-elevation reconstruction (Konark: ASI/Archnet plans, Nalanda/Taxila: excavation plans), not wall-and-bastion tracing.
0c. Merge into one `data/sites.csv` (id, name, type, lat/lon, source, confidence, duplicates). Geocode via OSM/Wikidata through the Action. Output: counts per tier-eligibility. Nothing else is trustworthy until this exists.
1. **Auto-T1 pipeline** — *built (prototype, 2026-11-03)*: `fetch-geometry.yml` → `build-traces.yml` (`tools/build-t1.mjs` → `data/traces/<id>.trace.json`, schema `in-rts.trace/1`) → `src/levels/t1.js`. Sites with no mapped outline get a location-only scene. Remaining: a matrix input on `fetch-geometry.yml` for 100-site batches; run batches 2+ now that Phase 0 has landed.
2. **Tier-2 template.** Now defined as *overlays on a T1 trace*: a plan-raster tool registers a drawing in the trace frame, traced elements get `plan:` srcs, eras become `diffs`. Prove on Reis Magos (fold the hand level's POIs, stair and pavilions into its trace) and Gwalior, then ~10-15 sites per chat for the ~300 priority sites. Temples/monasteries use the same tool with their own element kinds (`temple`, `stupa`, `cell-block`).
3. **Flagships to T3/T4.** The curated 10 first (Janjira is the model), then Maharashtra, Rajasthan, Deccan, Tamil, Goa groups, with user visual review.
4. **Scale/engineering.** Region index, budgets, CI sample and lazy loading exist; still to do: atlas navigation from the index, git-lfs or release assets if `data/traces` passes ~500 MB.

## Gates and honesty rules
- The ledger/`sites.csv` is the source of truth; a site is "done" only when its tier is recorded and evidence cited.
- No fabricated detail: T1 sites show only mapped facts.
- Licences: OSM (ODbL) attribution and share-alike apply to derived data; check before redistributing.
